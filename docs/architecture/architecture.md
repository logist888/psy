# Technical Architecture

Дата: 2026-08-19. Следует из PRD; активируется после валидации. Принцип: **не over-engineer MVP** — масштаб первого года мал (см. Scale), риск — спросовый, не технический.

## 1. Scale assumptions

| Горизонт | Психологи (MAU) | B2C визиты/мес | Прохождений/мес | Пик RPS |
|---|---|---|---|---|
| MVP (M0–M6) | 300–1 500 | 5–30 тыс. | 3–15 тыс. | <10 |
| Year 1 | 2–5 тыс. | 50–150 тыс. | 30–80 тыс. | <50 |
| Year 3 | 10–25 тыс. | 300 тыс.–1 млн | 150–500 тыс. | <200 |

Вывод: один регион, один Postgres с репликой, вертикальное масштабирование — достаточно на 3 года. Никаких k8s/микросервисов/Kafka.

## 2. Ключевые решения (Decision → Reason → Alternative → Trade-off → Reversibility → Cost)

| Решение | Почему | Альтернатива | Trade-off | Обратимость | Стоимость |
|---|---|---|---|---|---|
| **Next.js (App Router) + TypeScript, монолит** | SSR/SSG для SEO-страниц паспортов + один язык на всё; скорость соло-разработки с Claude Code | SvelteKit; Rails | Vendor-тренды Next | Высокая (страницы — React) | 0 |
| **PostgreSQL (managed, РФ-облако)** | Реляционная модель тестов/версий/результатов; JSONB для DSL методик; FTS для поиска | MySQL; Mongo | — | Средняя | ~15–30 тыс. ₽/мес |
| **Хостинг: Yandex Cloud или Selectel (RU)** | 152-ФЗ локализация — жёсткое требование [R4] | VK Cloud | Нет глобального CDN | Средняя | в V9 |
| **Поиск: Postgres FTS + pg_trgm** | ≤100 методик и ≤10 тыс. страниц — Elasticsearch не оправдан (прямой запрет промпта на карго-культ) | Meilisearch (self-hosted) при росте | Нет семантики (добавим pgvector при нужде) | Высокая | 0 |
| **Очереди/джобы: pg-boss (поверх Postgres)** | PDF-генерация, AI-вызовы, письма — низкий объём | Redis+BullMQ | Меньше throughput (не нужен) | Высокая | 0 |
| **Кэш: без Redis в MVP** | Нагрузки нет; Next/CDN-кэш статики достаточно | Redis | — | Высокая | 0 |
| **Auth: собственный (bcrypt/argon2 + сессии) либо Auth.js, email+пароль** | Санкционная устойчивость (без западных IdP), простота | Keycloak | Больше своего кода безопасности | Средняя | 0 |
| **Платежи: ЮKassa (+СБП)** | RU-эквайринг, подписки | CloudPayments | Комиссия 3,5% | Средняя | V16 |
| **AI: YandexGPT / GigaChat API; интерфейс-абстракция провайдера** | 152-ФЗ: health-данные нельзя западным LLM [R4]; в LLM уходят только **деидентифицированные структурированные баллы** | Self-hosted (Qwen) при росте цен/качества | Качество ниже фронтир-моделей — компенсируем шаблонной генерацией | Высокая (абстракция) | V8 |
| **Аналитика: self-hosted PostHog CE в RU-контуре** | Никаких западных пикселей на флоу результатов (FTC/BetterHelp-урок [R4]); продуктовая аналитика нужна с 1-го дня | Matomo | Поддержка своими руками | Средняя | ~5 тыс. ₽/мес |
| **CMS методик: своя админка в монолите** | Workflow Draft→Reviews→Published специфичен (права+наука); внешние CMS не дают модель прав | Strapi/Payload | Свой код | Средняя | время |
| **PDF: серверный рендер (Playwright/Chromium print) из HTML-шаблона** | Один шаблонный стек с вебом | pdfkit | Тяжелее контейнер | Высокая | 0 |
| **Скоринг: серверный** (в отличие от psytests) | Ключи = актив и юр. обязательство; клиент не видит ключей | Клиентский (дёшево, но ключи утекут) | +нагрузка (ничтожная) | — | 0 |

**ADR-достойные (необратимые/дорогие):** ADR-001 RU-хостинг и RU-LLM-контур (юр. основание); ADR-002 серверный скоринг и закрытые ключи; ADR-003 версионирование тестов/скоринга/норм (см. data-model); ADR-004 деидентификация перед LLM. Формат ADR — файл в `docs/architecture/adr/NNN-*.md` при принятии.

## 3. Security threat model (MVP baseline)

| Угроза | Вектор | Контроль MVP |
|---|---|---|
| Account takeover психолога | Слабые пароли, фишинг | Argon2, rate-limit, email-подтверждение критических действий; 2FA — SHOULD |
| Утечка результатов клиентов | SQLi/IDOR/дамп БД | ORM-параметризация; авторизация на каждом ресурсе (клиент принадлежит психологу); шифрование чувствительных полей (ответы/баллы) app-level (AES-GCM, ключи в KMS облака); минимизация ПДн клиентов (псевдонимы) |
| Enumeration результатов | Подбор ссылок | UUIDv4/ULID + подписанные токены ссылок с TTL |
| Кража ключей скоринга | Клиентский код, экспорт | Скоринг только сервер; ключи не в репозитории публичных ассетов; доступ к CMS по ролям |
| Скрейпинг библиотеки | Боты | robots-политика, rate-limit; паспорта методик — открыты намеренно (SEO/GEO-актив), стимульный материал закрытых методик — за auth |
| Prompt injection в AI-слой | Текст заметок психолога в промпте | В LLM не передаётся свободный текст пользователей в MVP — только структурированные баллы/нормы (белый список полей) |
| AI data leakage | Логи провайдера | Договор с провайдером (no-training), деидентификация, логирование запросов без содержимого |
| Инсайдер/админ | Широкие права | Аудит-лог доступа к результатам; принцип наименьших привилегий |
| Бэкапы/экспорт | Незашифрованные дампы | Шифрованные бэкапы, тест восстановления, retention бэкапов ≤30 дн |
| Инцидент 152-ФЗ | Утечка | План реагирования: РКН 24/72 ч [R4]; контакт юриста в runbook |

## 4. Privacy by design

- Минимизация: клиент психолога = псевдоним/код + пол/возраст (для норм); email клиента не обязателен; B2C — полностью аноним (stateless-ссылка результата, приём psytests).
- Согласия: отдельный экран согласия клиента до первого вопроса (152-ФЗ: отдельный документ, с 01.09.2025 [R4]); версия и timestamp хранятся; согласие на AI-обработку — отдельным пунктом.
- Retention: результаты клиента — пока активен аккаунт психолога + политика (12 мес неактивности → уведомление → удаление); B2C — не храним.
- Права субъекта: удаление/экспорт клиентских данных по запросу через психолога (оператор/поручение — конструкция LEGAL REVIEW); DSAR ≤30 дней.
- Разделение контуров: health-шкалы — только проф. контур; врозь тегируются в БД (data category) для раздельных политик.

## 5. SEO/GEO product architecture (entity system)

Сущности-страницы: **Методика (паспорт)** — ядро (интент «{методика} онлайн/ключи/нормы»); **Конструкт** (тревожность, выгорание — хаб, осторожно с YMYL); **Автор**; **Батарея-шаблон** (проф. интент «батарея при тревожном запросе»); **Гайд** (проф. how-to). Связи: конструкт→методики; автор→методики; методика→батареи.
Правила: каждая индексируемая страница обязана иметь уникальную ценность (паспорт ≠ тонкая обёртка: психометрика, нормы, права, ограничения); клинические конструкт-хабы — не создаём без клинического E-E-A-T [R5]; schema.org (MedicalWebPage НЕ используем — wellness-рамка; Quiz/Article/BreadcrumbList — да); hreflang — при появлении EN; канонизация вариантов форм методики.
URL: `/tests/{slug}` (паспорт+прохождение B2C), `/methods/{slug}` (проф. паспорт), `/constructs/{slug}`, `/authors/{slug}`, `/guides/{slug}`.
GEO (AI-ассистенты): открытые паспорта с цитатами и именованными ревьюерами; llms.txt; не блокировать AI-краулеров на паспортах (в отличие от psytests — их выбор отдаёт нам эту поляну [R1]).

## 6. Компоненты (монолит, модули)

```
apps/web (Next.js): public site (SEO) · client test-run · pro cabinet · admin CMS
packages/engine: декларативный test-DSL, скоринг, нормы (см. test-engine.md)
packages/db: Prisma/Drizzle схема (см. data-model.md)
packages/ai: провайдер-абстракция, промпт-шаблоны, деидентификация, фильтры вывода
packages/reports: HTML→PDF
infra: IaC (Terraform) для RU-облака, бэкапы, мониторинг (Uptime + Sentry self-hosted/RU-совместимый)
```
